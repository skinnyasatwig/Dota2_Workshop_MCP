# Dota map automation capabilities

This is the plain-language answer to “what can the MCP do without Hammer now?”

| Capability | Status | What it means | Remaining limit |
|---|---|---|---|
| Engine readiness diagnosis | Ready and demonstrated | `map_engine_readiness_probe` performs one command-free diagnostic launch, records game-state transitions, console evidence, dialogs, and a screenshot, then always shuts down. It can instead restore, focus, attach to, and preserve a user-started tools session. Fresh request IDs prevent replayed console history from masquerading as readiness. | The probe deliberately sends no corrective gameplay command, so it may report a dashboard state that the navigation runner can now resolve automatically. Historical direct-renderer NVIDIA failures remain machine-specific evidence. |
| One map specification | Ready | Build, terrain, sync, preview, validation, and engine-route tools read the same checked JSON contract. | A malformed or ambiguous contract is rejected instead of guessed. |
| Terrain generation | Ready | Rectangles, circles, rings, paths, polygons, named regions, water, height, tilesets, cliffs, and ramps can be generated repeatably. | Freeform decorative meshes, holes, arches, and curved world geometry still need Hammer or more Valve-format research. |
| Reuse and symmetry | Ready | Regions, paths, and whole components can be mirrored and placed repeatedly with automatic name isolation. | Visual composition still needs a human eye. |
| Safe writes | Ready | Dry-run reports, staging, backups, transactional replacement, and rollback protect source and compiled maps. | Git remains the long-term history; transaction backups are short-term recovery. |
| Checked solid volumes | Ready for boxes and flat/sloped convex volumes | Camp bounds, general/hero/Dota triggers, boss-attack areas, no-ward zones, and player blockers can use boxes or three- to 64-sided convex footprints. A footprint may provide coplanar bottom/top corner heights for a safe sloped solid. Generation, exact drift repair, mirroring, preview, and offline blocking follow the real shape. Valve's converter and compiler are both tested. | Arbitrary classes, concave footprints, twisted faces, truly curved solids, and general world meshes are rejected; base/FoW point blockers use separate Valve entities. |
| Checked world solids | Ready for flat or per-corner-sloped convex/concave extrusions | `managedSolids` turns one validated simple outline into a named, always-solid `func_brush`. A flat height or paired bottom/top height rings define the extrusion. The MCP keeps heights attached through mirroring, deterministically triangulates top/bottom faces, closes the sides, rejects open/non-manifold topology, detects drift, previews the true shape and uphill direction, and blocks the true concave footprint offline. Valve's converter and compiler accepted both repository L-shaped fixtures. | One outline cannot contain holes. Curves, arbitrary triangle soups, moving geometry, and decorative material composition remain unsupported. |
| Checked point blockers | Ready from official definitions | Team-aware `npc_dota_base_blocker` entities and explicitly linked `ent_fow_blocker_node` chains have reusable builders, validation, and preview lines. | Their final team collision and fog behavior remain targeted engine facts not covered by the route acceptance run. |
| Diagnostic preview | Ready | A top-down image shows terrain, contours, cliffs, ramps, water/currents, paths, entities, tower ranges, camps, objectives, minimap bounds, checked concave world solids, checked volumes (with uphill arrows on sloped solids), holes, unreachable areas, bright-cyan exact convex PHYS outlines, medium-cyan mesh envelopes, green-cyan curved primitives, muted-cyan bounds fallbacks, approximated obstruction circles, and unresolved props. | It is a diagnostic drawing, not the final in-game rendering. |
| Minimap consistency | Ready for north-up and Valve legacy-rotated overviews | `map_validate` checks the VMAP bounds, overview metadata/assets, PNG dimensions, and exact world/image/display transform. `map_engine_visual_test` adds one guarded launch, discovers the native HUD rectangle, verifies foreground at mouse-down, clicks normalized probes, reads the exact client camera through an optional Panorama bridge, and shuts down. Valve's `rotate` is correctly treated as a 0/nonzero one-quarter-turn flag, not degrees; the fixture includes Valve's shipped `rotate=15` convention. The north-up 3v3 map passed five measurement probes and a separate renderer-native PNG probe at 63 units of error. | Rotated click math is grounded in Valve's client source and offline-tested, but the live acceptance run is currently north-up. Valve can rename native HUD panel ids; an explicit rectangle is the safe fallback. Final artistic quality remains a human judgment. |
| Offline reachability | Ready for generated concave solids and static Rubikon PHYS families | The tile grid can find holes, trapped spawns, isolated land, blocked entrances, inaccessible objectives, bad path segments, checked player-blocker footprints, and checked concave world-solid footprints without launching Dota. Collision-enabled props are inspected through VRF in shadowing order: loose compiled addon model, packed addon `pak01_dir.vpk`, then base Dota VPK. Per-part bind poses are applied; convex `RnHull_t` vertices produce exact top-down outlines, mesh vertices produce conservative convex envelopes, and decoded spheres/capsules retain their primitive data. Round shapes use 32 tangent half-planes for a tight conservative outer projection after bind poses, entity pitch/yaw/roll, and non-uniform scale. Render and hitbox bounds are never substituted. | The 32-sided curved outline has slight intentional overshoot, and unknown Valve-authored concave mesh details remain conservatively enveloped. Exact trees, dynamic collision, team-selective blockers, and Valve's compiled navigation remain engine facts. |
| Real Dota navigation | Ready and demonstrated end to end | `map_engine_nav_test` can compile, launch through Steam, wait for the real render window, close only the exact watchdog stall popup, explicitly load the map when needed, require a fresh DebugSDK handshake, run correlated/chunked GridNav checks, suggest bounded repairs for blocked or disconnected endpoints, and shut down. `test:engine-nav-map` provides a dry-run-first project CLI and saves a structured report. The corrected 3v3 map passed all 4 routes and all 64 checks in one autonomous run. | It remains a comparatively expensive Windows/Dota integration test; final dynamic gameplay and visual behavior still need targeted engine checks. |
| Reusable Dota structures | Ready, including segmented base walls | Bases, Ancients, towers, fountains, shops, camps, boss pits, player starts, gates, and walls have checked builders. Camps can create spawn boundaries; boss pits can create polygonal no-ward volumes. A wall outline expands into overlapping convex player blockers, allowing practical curved/concave silhouettes while keeping every generated solid compiler-safe. | Decorative wall meshes, sloped wall runs, attackable-area design, and final visual dressing still need explicit design or Hammer. |
| Valve recipe library and safe refresh | Ready and evidence-gated | Terrain cores, cliff/ramp patterns, volume topology, point blockers, and Valve prefab references are catalogued. The doctor/catalog compare installed metadata plus five authoritative hashes to the proven baseline. `map_recipe_refresh_report` identifies affected families, prepares a candidate, and requires build, unit/integration, smoke, compiler-fixture, and acceptance-map evidence. The CLI safely runs the four non-engine checks. | The MCP deliberately cannot record or auto-bless a new baseline; a maintainer must review passing evidence and commit the candidate separately. |
| Entity validation | Ready for official FGD semantics | Known classes, inherited properties, basic types, dropdown choices, explicit numeric bounds, and resolvable named-entity links are checked against installed Valve definitions. The entity catalog exposes the same useful constraints before generation. | Runtime-only behavior, dynamic/wildcard targets, and undocumented custom metadata cannot be proven by FGD files. |
| Automated verification | Ready | The TypeScript build, unit/integration tests, MCP smoke suite, real 3v3 contract sync, preview, reachability, FGD checks, compile, autonomous launch/load/navigation/shutdown, real minimap click/camera measurements, and renderer-native Source 2 PNG evidence are reproducible. Engine images are correlated to a newly created stable file and rejected when black or uniform. | Final aesthetics and gameplay feel still need human judgment. |
| Repository compile fixture | Ready and demonstrated | `npm run test:compiler-fixture` applies a checked-in MCP-authored entity/volume payload, including a sloped gameplay volume plus flat and sloped concave L-shaped world solids, to Valve's locally installed blank map, round-trips it through `dmxconvert`, compiles a real VPK, and removes the isolated temporary addon. It uses no private 3v3 files and copies no Valve VMAP into Git. | The opt-in proof requires a Windows machine with Dota Workshop Tools; ordinary unit tests remain engine-free. |
| Repository engine-navigation fixture | Ready and demonstrated | `npm run test:engine-nav-fixture` builds a uniquely named disposable addon, proves one open route and one deliberately disconnected route in real GridNav, asserts the exact repair suggestion, reports console errors, closes Dota, and removes both addon trees. DebugSDK 1.4.0 also includes the optional client camera telemetry channel. | The proof is opt-in because a normal Workshop Tools launch takes roughly two to three minutes on the acceptance machine. Dota must be closed first. |

## What “minimal Hammer interaction” means

Most layout iteration can now happen in JSON plus generated previews. Simple flat or sloped convex/concave world solids no longer require Hammer. Hammer is still the right tool for final visual dressing, freeform mesh sculpting, and visual inspection. The goal is not to pretend Hammer no longer exists; it is to reserve Hammer for the parts only Hammer can reliably judge.
